# TRUSTRAIL Security Cloud — Bug Fix & Hardening Log

**Audit Period:** 2026-11-19 to 2026-11-20  
Every defect and hardening gap identified during inspection, TypeScript checking, Vitest execution, and live HTTP smoke testing was resolved in code and verified with automated tests.

| ID | Severity | Component / File | Root Cause | Resolution | Verification Evidence |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **BUG-01** | **CRITICAL** | `lib/security/crypto.ts` | Ephemeral per-module session secret caused 401 mismatches across Next.js route bundles. | Persisted fallback 256-bit key in `.data/.session-secret` (`0600`) shared via `globalThis`. | Live HTTP `:3000` login & authenticated endpoints return `200`. |
| **BUG-02** | **CRITICAL** | `lib/engines/scanner-engine.ts`, `lib/security/crypto.ts` | Secret redaction missed Bearer/Stripe/DB URI patterns and co-located SAST findings leaked secrets. | Expanded regexes and enforced `redactEvidenceSecrets` universally in `executeUnifiedScan`. | `tests/unit/engines.test.ts` & `api-and-security.test.ts`. |
| **DEF-01** | **CRITICAL** | `lib/security/vault.ts`, `lib/security/connector-config.ts` | Connector secrets in `connectors.config_json` were stored as plaintext JSON instead of encrypted envelopes. | Implemented versioned `AES-256-GCM` vault with `{orgId}:{connectorId}` AAD binding and `/api/v1/connectors/rotate-secrets`. | `tests/unit/security-hardening.test.ts` & `vault-scanners-sbom-recovery.test.ts` (0 plaintext verified in raw SQLite). |
| **DEF-02** | **HIGH** | `lib/security/auth.ts`, `app/api/v1/auth/**`, `team/route.ts` | No JWT `jti` revocation, no user `Disabled` status enforcement, no brute-force lockout, no TOTP MFA, no password reset/email verify. | Added `revoked_tokens`, `login_attempts`, `auth_verification_tokens`, `users.status`, RFC 6238 TOTP MFA, logout/refresh revocation. | `tests/integration/auth-mfa-lockout.test.ts` (all 4 suites pass) + live `:3000` logout -> `401`. |
| **DEF-03** | **HIGH** | `lib/security/ssrf.ts`, `lib/integrations/tls-inspector.ts` | SSRF lacked port restrictions, hop-by-hop redirect checks, and X.509 TLS inspection. | Restricted default ports to `[80, 443]`, added `fetchWithSafeRedirects`, and `node:tls` cert inspector. | `tests/unit/security-hardening.test.ts` & `integrations-and-apikeys.test.ts`. |
| **DEF-04** | **HIGH** | `lib/db.ts`, `lib/org-provisioning.ts` | Non-atomic org provisioning and ambiguous connector states (`Connected` vs `NOT_CONFIGURED`). | Wrapped org setup in `withDbTransaction` and added truthful `availabilityState` (`AVAILABLE`, `NOT_CONFIGURED`, `CONNECTED`). | `tests/integration/integrations-and-apikeys.test.ts`. |
| **DEF-05** | **HIGH** | `app/api/v1/api-keys/**`, `lib/api-response.ts`, `scans/route.ts` | API keys lacked fine-grained scopes, TTL expiration, key rotation, and brute-force protection. | Added `scopes_json` (`read`,`scan`,`write`,`admin`), `expires_at`, `/rotate` route, and failed-key rate limiting. | `tests/integration/auth-mfa-lockout.test.ts`. |
| **DEF-06..11** | **MEDIUM/LOW** | Scanners, SBOM, Policy Modes, AWS SigV4, Remediation, Recovery, Metrics, Jobs | Missing polyglot lockfiles/GHA rules, SPDX 2.3/SLSA 3, org `enforcementMode`, AWS STS SigV4, gated remediation, verified backup restores, background job DLQ, and Settings/MFA UI controls. | Implemented all modules, database schema v4, 63 OpenAPI-documented routes, and wired full frontend UI in `use-trustrail.tsx` + module views. | `tsc --noEmit` (0 errors), `eslint .` (0 errors), `next build` pass, 39/39 Vitest pass. |
| **TYPE-01..04** | **MEDIUM** | `rotate-secrets/route.ts`, `jobs/route.ts`, `remediation/route.ts`, `lib/db.ts` | Build-time TypeScript errors on `rotateSecretEnvelope` arg count, Zod v4 `z.record(key, val)`, implicit `RemediationRunRow`, and missing `verifyAuditChain` export. | Fixed signatures, explicit Zod key schema, typed row interface, and exported `verifyAuditChain`. | `npm run typecheck` passes with 0 errors. |
